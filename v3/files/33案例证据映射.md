# 33 个案例：任务、机制与商业关联证据台账

日期：2026-10-24 初稿；2026-10-26 内容修订。与《研究内容重构方案》配套。保留原案例序号和 feature-id，不改变网站。

**口径**：33 条包括当前 V2 默认展示的 28 条与 5 条对照。所有“用户问题”是研究任务假设；竞品机制是材料记录；用户收益是推导；商业关联均待验证。产品名称由原案例及发布来源共同识别。

**目标代码**：A 降低专业学习成本；B 提高规模化配置与交付效率；C 提高跨产品场景任务效率；D 提高日常运维与排障效率；E 探索 AI 辅助。B 的单次自动生成/任务编排只支持局部效率，不自动证明规模化。C 的方案协同不自动证明运行期跨产品配置。

**商业代码**：G1 场景化项目交付；G2 工程商学习、部署与运维成本；G3 持续使用、服务和推荐；G4 组合销售与场景扩展。代码只表达假设路径，不是归因结论。

**六易关系**：六易是坤灵已有的业务目标说法，商业代码是本研究按工程商任务做的拆分；对应只表示业务语义关联，不是效果结论。报告使用业务目标名称与五组机制，台账保留编码便于核对。

| 商业目标 | 对应六易 |
|---|---|
| G1 场景化项目交付 | 易装、易卖 |
| G2 工程商学习、部署与运维成本 | 易学、易用、易维 |
| G3 持续使用、服务和推荐 | 易用、易维 |
| G4 组合销售与场景扩展 | 易买、易卖 |

**机制引用短名**：说清配置收益；资料同源状态随行；复用配置保留例外；对齐对象与时刻；变更可退自动可查。“结论标明把握程度”位于“对齐对象与时刻”下，仅 UniFi 的覆盖预测、AI 安全告警、Matter 三例支持。

## 1. UniFi / 自动建墙 · feature-1（正式案例）

**产品**：UniFi Design Center。

- **工程商任务（研究假设）**：把客户图纸准备成可规划底图

- **已记录竞品机制**：空状态提供三个入口——拖入图纸（JPG/PNG/PDF）、示例平面图、扫码跳转 LiDAR App；导入后墙体自动生成，随后出现"Add Devices"。

- **潜在用户价值（机制推导）**：减少底图录入，仍需核对与纠错
- **商业目标最终映射**：G1/G2
- **商业关联（全部待验证）**：G1/G2：准备工时路径
- **适用条件与限制**：需识别模型和可编辑墙体；走查只到替换确认，未执行识别；不可撤销替换可能增加返工
